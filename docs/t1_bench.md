**Reading and limits.** The decode speed of one stream is 78.0 tok/s, so one laptop hour of single-stream decoding is about 0.66 reference hours by this proxy; every run produced exactly 256 tokens (no short output), so the decode formula is valid even though ollama ignores `ignore_eos`. **The factor is not the official one**: the backend (llama.cpp against vLLM), the quantisation (Q4_K_M against AWQ), the context (ollama truncates the ~3,000-token prompt to its 4,096 window, so "prompt tok" reads 4,096) and the batching (ollama serves the 4 requests one after the other, hence 36.9 tok/s) all differ, and `bench_llm.py` itself warns that the factor is then not comparable (model name and bench version differ from the reference). The earlier week-0 ollama proxy (62 tok/s generation in `docs/t1_week0.md`) was a different prompt. The measured number is therefore a **lower bound on the single-stream decode ratio, not a conversion rate for GPU-hours**: laptop hours must not be converted with 0.664 in the report until T3's JSON exists and the same vLLM checkpoint has been served on this machine (vLLM is not installed; installing it would replace torch, which the plan forbids). `scripts/serve_llm.py` plus `scripts/bench_llm.py --reference outputs/bench/t3-5070ti_qwen3-8b.json` is the command once both exist.
